## Review And Repair Ledger

**JLR-F01: certificate-side numeric identity was not strictly decoded.**
The initial mechanical run had root
`fe9b3b951766cd0bec103c81d453313e7d88eecd943193ba98b94985d4cf77e5`.
Independent review found that its reader accepted JSON `traceOutput: [true]`
against returned `output: [1]`, because Python equates booleans with integers.
The Lean encoder used the returned output, erasing the malformed certificate
field. This violated JLR-06's replay-boundary claim, not the semantics of a
Java-produced certificate: the typed Java probe emits integer identities.

The main agent reproduced the smallest witness on actual row 2: AND/FORBID,
flat singleton source atom 1. The old reader accepted all 2,356 rows after
changing only that field and generated byte-identical Lean input.

The repair validates all three identity arrays with exact integer types before
comparison, including empty rows. It also validates numeric schema/row IDs and
empty-result certificate absence. Six additional tests cover Boolean and float
certificate IDs, Boolean schema/row IDs, null empty output, and a certificate
on an empty rejection. JLR-06 now explicitly quantifies over its registered
finite negative controls, not every conceivable malformed auxiliary field.

The [initial review](evidence/superseded/acgn-java-lean-refinement-review.md)
and initial run archive are preserved under `evidence/superseded/`. Its recorded
mechanical `VERIFIED` is **superseded and not the final accepted result**.
The [delta review](evidence/acgn-java-lean-refinement-review-followup.md) independently
replayed the Boolean and float witnesses, confirmed rejection, accepted the
unchanged actual payload, and confirmed the 22 boundary tests: **PASS for the
repair delta**. Reviewer opinion does not replace the final new-root builds.
