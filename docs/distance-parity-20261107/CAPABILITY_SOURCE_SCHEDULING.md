# Capability Source Scheduling

The fixed 5,500-pair capability corpus exposed a regression shared by Fast
Rewrite and Certificate-Integrated normalization. All model and metadata hashes
matched the older 5,500/5,500 run; the newer frozen candidate recovered 5,160 on
each path. Equal cross-path scores did not establish recovery of expected
equivalences.

Controlled source builds around `ef46feae` localized the demonstrated failures
to unused-binder normalization. That change simplified Boolean bodies inside a
binding scope before liveness, but the equivalent outside formula could simplify
only after prenex. Some prefixes consequently retained paid unused coordinates.
Other routes dualized a typed subset atom before applying its authenticated
source rewrite, losing the opportunity to use that rule.

## Schedule

`NormalForm.normalize` first marks inherited temporal snapshot reads using the
existing owner/import inventory. It then applies existing guarded source rules
with no assumed binding facts, performs its existing branch/NNF normalization, and only then
checks unused bindings. Commutativity and idempotence still occur after the
certification snapshot. No global early saturation is introduced.

Two necessary typing/composition checks accompany this schedule:

- Empty-relation cardinality folding requires `hasUnaryCardinalityOperand`.
  A relation-valued declaration marker such as `one none` is not a Boolean
  formula, despite sharing the ONE opcode.
- Variable-versus-empty-set expansion waits while binding facts are absent.
  After prenex, the existing checked rule consumes ONE/SOME admissions directly;
  SET and LONE do not imply nonemptiness. A broader cardinality fold was rejected
  because body simplification alone did not preserve observable parameter types.

All existing source identity, exact type, lexical scope, dependency, disjointness,
counting, residual-domain and temporal REF checks remain. The patch does not
remove certified alternatives, specialize behavior by model name, or exclude
corpus predicates.

## Evidence

`CapabilitySourceScheduling.lean` reuses `Phase5SourceRules` and
`UnusedGroupedBindings`. It proves contextual composition, contradictory and
tautological quantifier cases, typed subset/negation instances, admitted
nonempty-cardinality facts and retained empty/disjoint declaration controls.
These are semantic contracts, not a verified Java interpreter.

The earlier pass must not precede snapshot marking: a value bound in an earlier
phase need not belong to a mutable carrier in the current phase. The reused
`TemporalPhaseLocalBinding` counterexample and static-carrier theorem retain both
the mutable negative and static positive controls. Missing exact-type evidence
also cannot authorize a declaration-guard alias; that check now returns false
instead of dereferencing null in a synthetic untyped case.

`CapabilitySourceSchedulingTest` checks renamed structural family instances,
both native replay directions, tampered receipts and independently translated
bounded Alloy counterexamples. Its higher-order empty-SET witness uses the
compiled Lean contract because the Alloy SAT translator cannot negate that
assertion. Existing source-rule, typed-owner, certificate and performance suites
remain separate regression gates.

The original failed publication rows, controlled before/after builds, all 340
failure traces, subsequent 16-case scheduling counterexamples and per-candidate
receipts are retained in the workstation evidence directory
`capability-repair-v1`. Reported recovery must use the final candidate's complete
raw rows, never the earlier result. Full natural-corpus and public-certification
claims require their separate gates.

The capability report also classifies the five composed families explicitly;
the old underscore heuristic omitted `mixed` and counted several simple
families. The strict 5,500/5,500 closure assertion is unchanged.

## Natural-Corpus Scheduling Interactions

The first full natural run on the capability repair had no native path mismatch,
but lost six previous zero-distance pairs while gaining three. Five losses were
one membership-quantifier family: early distribution of `x not in B & C`
prevented the existing checked single-membership eliminator from recognizing it.
The sixth exposed a neutral `true` sibling after descoping; that sibling blocked
the remaining universal from lifting before it was removed later.

The followup applies the unchanged membership eliminator in a linear pre-prenex
walk before source expansion, and repeats that pre-prenex source cleanup after
descoping. It never invokes the new walk after declaration ownership is issued.
There is no new saturation loop or relaxed admission gate. Shared Lean laws cover
both schedules, carrier premises, neutral quantified restrictions and the SET/LONE
negative controls. Fresh candidate-specific execution, zero-preservation and
full-domain results are still required; the first run remains retained evidence.
