# Fifth-Five Verification Boundary

This v2.17 package preserves the original statements and hashes of P3-04,
P3-05, P3-06, P3-12 and A2-12. The configuration freezes their bounded
surfaces, pass predicates, exclusions and trusted dependencies. A general
Lean contract and finite Java correspondence are distinct evidence; neither
source pins nor selected observations establish universal Java refinement.

The new profile uses the byte-pinned v2.13 verification engine and v2.14
dispatcher in private modules, following the fourth-five package. Earlier
profiles are not modified. Counted AST-literal replacements set this
package's paths; four fixed areas provide law, flat/container record, wire
table and source-binding evidence. The five claims, their scopes, registered
proof/test/extractor mappings and rejection predicates cannot be changed by
an edited configuration. Encoders, orchestration and compiler extractors
are tested components of the declared TCB, not self-proved implementations.

Each area fixes its observation census before evaluating Java output. It
must supply actual observations, independently reconstructed expected data,
general Lean contracts, generated Lean replay programs, false-proposition
controls and compiler-resolved source-change rejection controls. Missing
rows, unknown cases, duplicate records or empty control sets block the run.
The registered rejection diagnostic must be reached; a syntax error,
missing class, failed import, panic or resource failure is not evidence of
semantic rejection. All named Lean theorems have an axiom audit under the
configured foundational trust. Hash collision resistance remains trusted;
no hash-injectivity theorem is admitted.

Two isolated snapshots compile and run all configured Java observations and
Lean proofs. The runner compares proof inventory, observed artifacts,
generated provenance, negative controls and source controls. Only diagnostic
paths, timings and host identifiers may differ. All required source,
dependencies, tests, proof inputs, notes, configuration and CI entry points
are hashed before execution; any mutation invalidates that run. The local
deterministic Git commits used for certificate fixtures have TEST_ONLY
authority and are never experiment or release provenance.

Verification is offline after installing the pinned Lean toolchain. Each
command has a 900-second budget. A failure or incomplete run is retained
with its original input manifest; a repaired candidate must be checked
afresh. No successful result is inherited from the previous release.

The package creates no new rewrite rule or theory authority. A supported
producer, verifier or experimental-pipeline defect found while implementing
these obligations must be documented and repaired separately; any resulting
experimental behavior change requires fresh affected experimental results
before v2.17 publication. Preserved empirical results are not relabeled as
having been generated by a new source commit.
