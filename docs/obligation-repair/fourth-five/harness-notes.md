# Fourth-Five Closure Boundary

The v2.15 package retains the original statements and hashes of P2-20,
P2-18, A2-07, A2-11 and P3-03. The JSON configuration fixes their bounded
verification surfaces, trusted dependencies, pass predicates and blocking
conditions before execution. General Lean contracts and finite Java
correspondence are separate evidence, not whole-JVM refinement.

The runner instantiates the byte-pinned v2.13 engine in a private module by
counted AST-literal replacement. The fixed v2.14 dispatcher is likewise
instantiated with a new three-area table; previous modules and package files
are not mutated. These adapters, compiler extractors and trace encoders are
tested components of the declared TCB, not self-proved implementation code.

Each area fixes its observation and source-object census independently of
the observed rows. No missing row, plugin failure or empty control family
is replaced by a successful default. Every accepted proof theorem has one
axiom audit. The allowed foundational axioms are explicitly declared.
Negative controls must reach an actual false proposition in Lean or the
registered source-shape rejection in javac-resolved extraction. Syntax,
loader, panic and resource failures cannot count as semantic rejection.

Both isolated builds use fresh source snapshots and deterministic TEST_ONLY
Git provenance. They compile actual producer and verifier sources, replay
the fixed observations, execute rejection controls, and compare proof,
artifact and provenance inventories. Input or evidence mutation blocks.
All required inputs are hashed, including the configuration, this boundary,
the three area notes, test drivers, verifier sources, dependencies and CI
entry points. Diagnostic paths and timings are the only nondeterministic
output fields permitted by the configuration.

This is a finite assurance repair. It creates no new rewrite family or
certificate authority. SHA-256 collision resistance remains a cryptographic
assumption; no hash-injectivity theorem is claimed. Earlier empirical
results and full-corpus behavior are outside this run. Any failing candidate
is retained with its original input manifest before preparing a replacement.
